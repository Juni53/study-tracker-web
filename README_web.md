# Study Tracker (Web 版) — 移植の途中経過

`ui/` が、公開するサイトのルートです(GitHub Pages には、このフォルダを公開します)。
Python 版の UI(HTML/CSS/JS)はそのままで、Python 側(`data_manager.py` / `api.py`)を `ui/js/core/` へ JS で移植しています。

Python 版 `api.py` の公開メソッドは、すべて移植済みです。Web 版だけの API は、`request_notification_permission`(通知の許可)、
`get_storage_info`(保存先・容量・永続化の状態)、バックアップまわり(`localApi.js` の `WEB_ONLY_METHODS`)、
初回案内の `get_onboarding` / `complete_onboarding` / `get_onboarding_tags` / `apply_onboarding_tags`(最初に使う科目の選択)です。「案内を見たか」の印は、`settings.json` ではなく、
バックアップに含まれない「メタ情報」(`onboarding`)に持っています(別の端末で復元しても、その端末では初回の案内が出ます)。設定ページの「保存先」の表示は、このブラウザの中(IndexedDB)の状態を表示します。

## テスト

```
npm install
npm test            # 全テスト
npm run test:tz     # 4つのタイムゾーン(東京・ロサンゼルス・オークランド・UTC)で全テスト
```

- `tests/golden/pure.json`(純粋な計算)と `tests/golden/scenarios.json.gz`(状態を持つ処理)は、Python 版を「正解」として作った照合データです。
  - `scenarios` は、アプリの起動・記録・ショップ・タグ・試験・設定変更・ホーム/カレンダー/統計の問い合わせを、台本どおりに動かした結果(戻り値と保存データ)。手書きの場面と、乱数(シード固定)で作る長い場面があります。
  - 作り直すとき: `python tools/golden/gen_pure.py --src <元のアプリのフォルダ> --out tests/golden` と `python tools/golden/gen_scenarios.py --src <元のアプリのフォルダ> --out tests/golden`
  - 変更の確認には、コードをわざと壊して(変異)テストが落ちることを見る方法が有効でした。
- 照合で意図的に違えている点(安全側): 他の文字種の数字(アラビア数字など)は受け付けない／結果が無限大になる換算式は fallback にする。

## 画面を確かめる

ES モジュールを使うため、ファイルをダブルクリックして開く(`file://`)ことはできません。簡易サーバー経由で開きます(Chrome か Edge)。

```
python tools/serve.py        # → http://localhost:8000/   (止めるには Ctrl+C)
```

Windows では `python` の代わりに `py` と打つ場合があります。標準の `python -m http.server` は、Windows の環境によっては
.js を text/plain で返してしまい、ブラウザが読み込みを拒否することがあるため、専用のスクリプトを用意しています。
データはブラウザ内(IndexedDB)に、「アドレス(ポート番号まで)ごとに別々に」保存されます。ポート番号を変えると、別のデータになります。

## デスクトップ版のデータを取り込む(手順3)

1. デスクトップ版のあるパソコンで、`python tools/export_desktop_data.py` を実行する(`study_tracker_desktop_data_日時.json` ができる)。
2. Web 版の 設定 → データ管理 →『バックアップから復元』で、そのファイルを選ぶ。
3. 確認画面で内容(記録の件数・期間・ポイント)を見て、『上書きして復元』を押す。
4. ホーム・カレンダー・統計の数字を、デスクトップ版と見比べる。
5. 違っていたら、設定の『元に戻す』で、復元の直前の状態に戻せる(復元の前に、いまのデータを自動で控える)。

- 復元は、ファイルの中身を先に検証します。1つでも問題があれば、何も変更せずに理由を表示します(例: 日付として不正な記録を含む)。
- 『記録だけ統合』は、別の端末のバックアップから、足りない記録だけを足す機能です。ポイント・報酬・設定などは、いまのままです。
- Web 版のバックアップ(`study_tracker_backup_日付.json`)も、同じ『バックアップから復元』で読み込めます。
- バックアップのリマインダーは、設定で周期(毎週 / 2週間ごと / 毎月 / 通知しない)を選べます。起動時、周期がたっていれば右下に小さく出ます。

## 公開(GitHub Pages)の手順

リポジトリ: `Juni53/study-tracker-web`。公開後のアドレスは `https://juni53.github.io/study-tracker-web/` です。
(GitHub Pages は、無料のプランでは、公開(public)のリポジトリだけが対象です。)

1. このフォルダの中身を、リポジトリのフォルダにコピーして、`main` ブランチに commit・push する(`.github/` も含める)。
2. リポジトリの **Settings → Pages → Build and deployment → Source** を **GitHub Actions** にする(最初の1回だけ)。
3. **Actions** タブで「Deploy to GitHub Pages」が動く。テスト(4つのタイムゾーン) → ビルド → 公開の順で、すべて緑になれば完了。
   - 以降は、`main` に push するたびに、自動で、テストを通してから公開される。テストが1つでも失敗すると、公開されない。
4. 公開されたアドレスを Chrome / Edge で開く → アドレスバーの右の「インストール」(または、設定ページの「アプリとしてインストール」)。
5. `main` 以外のブランチ名にしている場合は、`.github/workflows/deploy.yml` の `branches: [main]` を直す。

**更新の仕組み**: push すると、ファイルの中身から決まる「版」(build)が変わる。公開済みのアプリを開いている人には、
右下に「新しいバージョンがあります」と出て、「更新する」で切り替わる(記録は、そのまま残る)。設定ページに、版が表示される。

**ビルドをローカルで試す**(オフライン・インストールの確認):
```
node tools/build-pwa.mjs --out dist      # dist/ ができる(ui/ は変更されない)
python tools/serve.py --root dist        # → http://localhost:8000/
```
開発中の `ui/`(`python tools/serve.py`)は、Service Worker を登録しないので、古い版が残って困ることはない。
ビルドした dist/ は、Chrome の開発者ツール → Application → Service Workers で確かめられる(「Offline」にチェックして、再読み込み)。

**公開しないもの**: 学習の記録(`study_tracker_desktop_data_*.json` など)は、リポジトリに入れない(`.gitignore` 済み)。
データは、各自のブラウザの中にだけ保存される。

## 見た目・操作の決まりごと(タッチ環境への配慮)

- **ホバーの見た目**は、必ず次の形で書きます(`tests/css.touch.test.js` が、すべての規則を確認します)。
  `@media (any-hover:hover){ :where(:root:not(.is-touch)) セレクタ:hover{ ... } }`
  - タッチ操作では、指を離したあとも `:hover` が残り続けるためです。
  - ホバーできる入力が無い端末(スマホ・タブレット)では、`@media` で無効になります。
  - タッチ画面つきのパソコン・Chromebook(マウスもある端末)では、触ったあとの間だけ `<html>` に `is-touch` が付き(`js/components/inputMode.js`。マウスを動かすと外れる)、そのあいだは出ません。
  - `:where()` は優先度を足さないので、`:active` の規則との強さの関係は変わりません。
- JS のホバー表示(星評価・カレンダーの吹き出し)も、`isTouchInput()` を見て、タッチ中は出しません。
- タップしたときの、ブラウザ標準の青いハイライトは、透明にしています(`tokens.css`)。
- **選択肢の列**(ラジオボタンのように1つだけ選ぶボタンの列)は、`components/radioGroup.js` の `bindRadioGroup(入れ物, 選ばれたときの処理)` で作ります。入れ物の中だけが対象になり、同じページの別の列には影響しません。

## 他の端末(同じ LAN / Wi-Fi)から開く

```
python tools/serve.py --lan        (Windows は start_lan.bat をダブルクリックでも可)
```

表示された `http://192.168.…:8000/` のようなアドレスを、同じ Wi-Fi につながっている他の端末で開きます。

- 公開するのは `ui/` の中身だけです(学習データは、各端末のブラウザの中にあり、サーバーには無い)。
- 接続を受け付けるのは、家庭内などのプライベートなアドレスの端末だけです。インターネット側からは 403 で拒否します。
- 初回は、Windows のファイアウォールの確認が出ます。『プライベート ネットワーク』だけにチェックして許可してください。
- カフェ・学校・ホテルなど、知らない人がいるネットワークでは使わないでください。
- 開けないときは、ゲスト用 Wi-Fi など『端末どうしの通信を禁止』している接続ではないか確認してください。

**http のアドレスでは、ブラウザの制限で使えない機能があります**(`localhost` だけは例外で、LAN の IP は例外になりません)。

| 機能 | LAN の http | 理由 |
|---|---|---|
| 画面・記録・ショップ・統計など、基本の動作 | 使える | |
| 保存(IndexedDB) | 使える | |
| 複数タブの防止(Web Locks) | **使えない**(防止が働かない) | HTTPS(または localhost)のみ |
| 永続化の要求(`storage.persist`) | **使えない** | 同上 |
| PWA(インストール・オフライン)、通知、画面消灯防止 | **使えない** | 同上 |

Chromebook / Windows の Chrome・Edge では、試験用に例外を設定できます。
`chrome://flags/#unsafely-treat-insecure-origin-as-secure`(Edge は `edge://flags/...`)を『Enabled』にして、
入力欄に `http://192.168.0.5:8000` のようにアドレスを書き、ブラウザを再起動します。iPad(Safari)にはこの設定が無いため、
PWA まで含めた確認は、公開後の https のアドレス(GitHub Pages)で行います。

別のネットワーク(自宅の外など)の端末で見たいときは、LAN のサーバーは使えません。公開後のアドレス(GitHub Pages)を使います。

## フィードバックタブの設定

`ui/js/config.js` の2つの定数で決めます(書き換えて `main` に push すれば、公開サイトに反映されます)。

- `FEEDBACK_URL`: フォームの URL(`https://` で始まるもの)。**空のままなら、タブごと出ません。** `https` 以外の値は、設定なしとして扱い、
  コンソールに警告を出します。Google フォームでは、短縮リンク(forms.gle/…)より、`docs.google.com/forms/d/e/…/viewform` の形が確実です。
- `FEEDBACK_VERSION_ENTRY`(任意): アプリのバージョンを、フォームの1つの質問に、入力済みで渡したいときの、質問の番号(例: `entry.1234567890`)。
  空のままなら、何も渡しません。渡すのは「バージョン」(例: `v3.0.0 (build 774a569215f3)`)だけで、記録・設定などの学習データは渡しません。
  番号は、Google フォームの「⋮ → 事前入力したリンクを取得」で、その質問に適当な文字を入れて作ったリンクの `entry.数字` の部分です。

どんな値を入れても、テストが通ること(= CI が止まらないこと)は、`tests/config.variants.test.js` が、「空」「URL あり」「URL + 質問番号あり」「https でない値」の4通りで確かめています。

設定すると、初回の案内の「プライバシー」にも、「外へ出るのはフィードバックのリンクを開いたときだけ(バージョンを渡す場合は、そのことも)」の一文が加わります。

## フォント

- 同梱しているのは、**JetBrains Mono**(可変フォント1つ。`ui/fonts/JetBrainsMono-Variable.woff2`、約72KB)だけです。タイマーなどの数字の見た目を、端末によらずそろえるためです。

- ライセンスは SIL OFL 1.1 です。`ui/fonts/OFL.txt`(全文と著作権表示)と `ui/fonts/README.txt`(出典・加工)を、フォントと同じ場所に置いてあります。**フォントを入れ替えるときも、同じ形で置いてください。**
- 作り直すとき: `pip install fonttools brotli` のあと、`python tools/make_fonts.py "JetBrainsMono[wght].ttf"`(元ファイルは google/fonts の `ofl/jetbrainsmono/`)。加工は、形式の変換だけです。
- 「CSS・HTML が読みにいくファイルは、すべて実在する」ことは、`tests/fonts.test.js` が確かめます(以前は、存在しないフォントを毎回読みにいっていました)。

## Python 版との意図した違い

Web 版は、Python 版と同じ計算・同じ保存形式で動くことを、Python 版を「正解」にしたテスト(`tests/golden/`)で確かめています。
ただし、次の点は、**意図して**変えています。

| 項目 | Python 版 | Web 版 |
|---|---|---|
| さぼり券の対象になる日 | 「勉強も起動もなかった日」だけ。アプリを開いただけの日(起動ログ `launch_log.json` にある日)に達すると、そこで遡るのをやめる | 勉強の記録がなかった日は、アプリを開いただけの日も対象にする。起動ログは、データの互換のため、今までどおり記録する |
| さぼりペナルティ(ポイントの消失)の金額 | 1 日ぶんの金額は、残高 × 割合を小数第 2 位まで丸めた値(例: 960.4 → -19.21) | 四捨五入した**整数**(ちょうど半分は切り上げ。例: 960 → -19、625 → -13)。金額が 0 に丸まる残高(割合 2% なら 25 ポイント未満)は、減らない |

- 変えたのは、`ui/js/core/dataManager.js` の `autoApplySabori` の、起動ログで遡るのをやめる1行と、ペナルティの金額を求める 2 か所(毎日の判定 `applyDecay`・過去の日付の記録を足したときの `_applyDecayForPastRecord`。どちらも `roundHalfUp`)だけです。
  既存の残高に小数が残っている場合、それはそのままです(これからのペナルティの金額が整数になります)。
- **照合のテストの作り方**: `tools/golden/gen_scenarios.py` は、Python 版の「コピー」に、`tools/golden/web_divergences.py` の変更を当ててから動かします(元の Python 版のファイルは書き換えません)。
  こうすると、「この表の違い以外は、Python 版と完全に一致している」ことを、全ステップで確かめ続けられます。
  当て先が見つからないとき(Python 版が変わったとき)は、止まります。
- 作り直し: `python tools/golden/gen_scenarios.py --src ../study_tracker_app --out tests/golden`。`--pure-python` を付けると、違いを当てない、元のままの Python 版で作ります(再生成が元と一致するかの確認用)。
- 違いを足すときは、`web_divergences.py`・この表・コードの注釈の3か所に書いてください(`tests/sabori.launch.test.js` が、3か所の記載を確かめます)。
- 台本の照合で、書き出し時刻(`exported_at`)と、`milestones_achieved.json` の並び(Python では集合由来で、実行のたびに変わる)は、比べるときに無視します。

## 日付が変わったとき

起動時の処理(さぼり券の自動適用 → ポイントの消失の判定)は、アプリを開いたときに実行されます。Web 版は、インストールしたアプリを開きっぱなしにしやすいので、
`ui/js/components/dayWatcher.js` が、**日付が変わったことを見張って**、日付の表示を新しくし、同じ処理をやり直し(`api.run_day_rollover()`)、画面を描き直します。
**ストップウォッチ(ポモドーロ)が動いていても、待ちません(保留しません)。**

- **見張りの方法**: 「次の 0 時」に 1 回だけ鳴るタイマー(`setTimeout`)です(60 秒ごとの確認は、やめました)。
  - 次の 0 時は、「明日の 0:00」を年月日から組み立てて求めます(夏時間の日は 24 時間ではないため)。0 時の 1.5 秒後に鳴らします。
  - 鳴ったら、必ず今日を取り直します(時計の変更・夏時間で、早く鳴ることがあります。まだ同じ日なら、張り直すだけです)。
  - 長いタイマーは、最長 1 時間で刻みます(スリープ・時計の変更でずれても、1 時間以内に追いつきます)。
  - ブラウザは、隠れているページのタイマーを間引きます(Chrome 88 以降は、5 分以上隠れたページを 1 分に 1 回まで)。だから、タイマーだけに頼らず、
    **画面が再び見えたとき・ウィンドウのフォーカス・`pageshow`・タブの切り替え**でも、すぐに確認します。
  - タイマーは `unref` します(`app.js` を読み込むテストが、プロセスの終了を妨げられないように)。
- **日付が変わったときの順序**: ① 見出しの日付の文字を入れ替える(`components/todayDate.js`。画面は描き直さない) → ② 起動時処理をやり直す(同じ日に何度やっても、二重には適用されない。テストで確認) → ③ 画面を描き直す。
  - 見出しの日付は、**全タブ**の、ポイントの左にあります(`2026-11-13 (金)`)。
  - 起動時処理のあと、ポイント残高(`components/points.js`)と、バックアップのリマインダーの判定も、新しくします。
- **画面の描き直しは、クロスフェード**です(`app.js` の `refreshActiveView`)。`document.startViewTransition`(同じページ内の View Transitions。既定の動きがクロスフェード)を使います。
  対応していないブラウザ、または「動きを減らす」設定のときは、アニメーションなしで、すぐに入れ替えます。見ている位置(スクロール)は保ちます。タブを切り替えるときの動きは、これまでどおりです。
  - **ストップウォッチとフィードバックのタブは、描き直しません**(views の `refreshOnDayChange = false`)。ストップウォッチのタブは、日付の文字とポイント残高だけが新しくなり、タイマー・ポモドーロには触れません。
  - 描き直しは、ポップアップが開いている間・入力中は待ち、閉じたあとに行います。待っているあいだにタブを切り替えると、新しい日付で描かれるので、描き直しません。
- **日付の更新を実機で試すときの注意**: Chrome 系のブラウザは、OS の設定で時計を進めた直後、`new Date()` が数十秒間、古い時刻を返し続けます(実機で確認。Firefox 系は、すぐに新しい時刻になります)。
  アプリは、ブラウザが返す時刻しか見えないので、その間は日付の更新が遅れて見えます。時計を飛ばす実験では、DevTools のコンソールで `new Date()` が新しい日付になったことを確認してから、フォーカスやタブの切り替えを試してください。
  実際の 0 時をまたぐ場合(時計を飛ばさない場合)は、この遅れは出ず、0 時の 1.5 秒後に更新されます。
- **タブを開くたびに**、日付が変わっていないかを確認します(変わっていれば、起動時処理のやり直しが済んでから、新しいタブを描きます)。
- **保留しない理由**(2026-11-02 に、実測で確かめました):
  - 描き直しても、ストップウォッチは止まりません(計測の状態は、画面ではなく、メモリ上のストア `store/stopwatch.js` にあります)。
  - 日をまたいで計測した記録は、「開始日」の日付で保存されます(Python 版と同じ)。その日に、さぼり券が自動適用されていても、記録を保存すると券が 1 枚戻ります(`dataManager.js` の `_refundSaboriIfNeeded`)。
    毎晩 0 時に更新が走る場合と、計測が終わるまで保留する場合とで、最終状態(券の枚数・使った日・連続記録・ポイント)は同じでした。違うのは、計測中だけ券が 1 枚少なく見えることだけです。

### 計測が日付をまたいでいる間の表示

計測の途中(開始日が決まっている)で、開始日が今日より前なら、「日付をまたいでいる」状態です(`ui/js/store/dayCrossing.js`。ストップウォッチのストアから導く、読み取り専用の状態)。
保存すると、記録は「開始日」の日付になるので、その日に関わる表示は、「保存すると変わる可能性がある(確定前)」ことになります。

- **規則は `isPending` の 1 行だけ**です。将来、「計測中全般」に広げるときは、`startDate !== null && startDate < today` を `startDate !== null` に変えるだけで済みます。
- 状態は、日付が変わったとき(`app.js` が、日付の見張りの `onDayChanged` から `refreshCrossing` を呼ぶ)と、計測の開始・一時停止・リセットのときに作り直し、中身が変わったときだけ、購読している側に知らせます。
- ストップウォッチの画面に、**開始時刻**が出ます(同じ日は「開始 23:05」、日をまたぐ間は「11/12 23:05 開始」。一時停止しても最初のまま、リセット・保存で消えます)。週ログには付けません。
- **全ページ**の右下に、お知らせ「計測が日付をまたいでいます」が出ます(`components/crossingNotice.js`。ストップウォッチのタブでも出ます)。
  「閉じる」で隠せます(同じ計測のあいだは、また出ません。保存・リセットで消え、新しくまたいだときは、また出ます)。
- **確定前の斜線**: 日をまたいでいる間、開始日(`pendingDates`)に関わる部分に、薄い斜線を重ねます(`components.css` の `.pend` / `.pend-swatch`、道具は `components/pending.js`)。
  線の色は `--ink-rgb` なので、ダークテーマでは、自動で明るい線になります。斜線の下には、**背景色(`--paper-rgb`。ライトならライトの背景色、ダークならダークの背景色)のオーバーレイ**を重ねます(1 つの `::after` に 2 層)。下にある棒・文字・マスの色を少し背景になじませて、斜線がどこでも同じ濃さに見えるようにします。
  濃さは `tokens.css` の `--pend-line-a`(斜線)と `--pend-wash-a`(オーバーレイ)で、ライト・ダークそれぞれ調整できます(ホーム・統計・カレンダー・ショップ・グラフ・お知らせの凡例の、すべての斜線が同じ値を使います)。
  折れ線グラフの重ね順は、面の塗り → 背景色のオーバーレイ → 斜線 → 線 → 丸です(線と丸は、斜線の上。くっきり保ちます)。
  数字・文字は読める濃さです。操作は妨げません(`pointer-events:none`)。
  - **ホーム**: 連続記録のカード / 週ログの開始日の行(日付の行全体) / 週間推移(開始日の点は中空の丸、その点から次の点までは破線、そのまわりに縦の斜線の帯)。
  - **統計**: 今週のログの開始日の行(日付の行全体) / 連続記録の行 / 今月の日別の棒(開始日の日) / 進行中の連続記録の帯(過去の帯は対象外)。
  - **カレンダー**: 開始日のマス / 連続記録の行。 **ショップ**: さぼり券の枚数。
  - **対象外**(斜線を増やしません): 今日・今月の目標、試験のカード、タグ別の内訳、ポイント履歴、ポイント残高、統計の概要、全期間の表示。ポップアップで補います。
  - 色・斜線だけに頼りません。斜線の部分には、`title`(ホバー)と読み上げ用の文字(`.sr-only`)、カレンダーのマスには `aria-label`、折れ線グラフには `role="img"` と `aria-label` を付けます。
  - 描き直しは、日付が変わったとき(起動時処理のあと)と、日をまたぐ状態が終わったとき(保存・リセット。静かに 1 回)に行います。
- `store/stopwatch.js` の開始日・開始時刻は、共通の時計(`core/dates.js`)から取ります(`new Date()` を直接使いません)。

## 待機画面(全画面)

ストップウォッチのタブの「⛶ 待機画面(全画面)」で開く、**見るだけ**の画面です(`ui/js/components/standby.js`・`ui/css/standby.css`)。机に立てかけたタブレットなどで、離れた場所から時間を読むためのものです。
内容は、現在時刻 / ストップウォッチ(状態・時間・開始時刻) / ポモドーロ(リング・残り時間・フェーズ・サイクル)です。操作(開始・一時停止など)は置いていません(うっかり止めないため)。時間・フェーズの音や通知は、いつもどおり鳴ります。

- **表示は 2 種類**です(画面の下のボタンで切り替え。選んだ表示は設定に保存され、次回も使います。保存先は、ポモドーロの設定の `standby_mode`。選んだときだけ保存し、無ければ「通常」)。
  - **通常**: テーマ色(ライト/ダークは、アプリの設定に従う)。動きません。
  - **有機EL**(スクリーンセーバー): 背景は**真っ黒**(`#000` = 発光ゼロ)、文字は真っ白にせず抑えた明るさ、線は細く、明るい面を作りません。
    焼き付き防止のため、表示全体が**ゆっくり少しずつ動きます**(40 秒ごとに行き先を変え、その間は一定の速さで移動。中心から ±3vmin の範囲。`driftPoint` が決まった道筋を作ります)。
    「動きを減らす」設定のときは、滑らかな移動をやめて、40 秒ごとに位置だけを変えます(焼き付き防止は続けます)。
- **全画面**: 使えるブラウザ(PC・Chromebook・Android・iPad)は、本物の全画面にします。使えないとき(iPhone の Safari など)や断られたときは、画面いっぱいの表示にします。
  Esc で全画面を抜けたら、待機画面も閉じます。閉じるのは、「閉じる」ボタン・Esc・全画面を抜けたとき。
  - 外部仕様の確認(2026-11-05): Fullscreen API は PC・Android・iPadOS の Safari で使えますが、iPhone の Safari では、動画以外の要素の全画面が使えません(WebKit のバグ報告は、2026-06 時点でも未解決)。
- **画面の消灯**: 開いている間は、設定(「計測中は画面の消灯・スリープを防ぐ」)に関わらず、消灯・スリープを防ぎます(`setStandbyHold`)。閉じたら元の設定に戻ります(設定が ON で計測中なら、防いだまま)。
  - 外部仕様の確認(2026-11-05): Screen Wake Lock API は、Chrome / Edge 84、Firefox 126、Safari 16.4 から使えます(ホーム画面に追加した Web アプリは、iOS 18.4 から)。
- **操作ボタン**(表示の切り替え・閉じる)は、4 秒操作がないと消えます(触れる・動かす・キーを押すと戻ります。キーボードで操作中は消えません)。
- **アクセシビリティ**: ダイアログ(`role="dialog"`・`aria-modal`)で、後ろの画面は操作・読み上げの対象外(`inert`)にし、フォーカスは待機画面の中に閉じ込めます。閉じたら、開いたボタンにフォーカスが戻ります。フェーズが切り替わると、読み上げ用に知らせます(目には見えません)。
- 開いている間は、後ろのページのスクロールバーを出しません(`html{scrollbar-gutter:stable}` の領域の確保も解除します。解除しないと、画面の右端が細い帯のように空きます。実際のブラウザで確認して見つけました)。
- 時間の文字・状態の文言・リングの計算は、ストップウォッチのタブと共通です(`components/timeFormat.js`)。

## 計測中の再読み込みの確認

ストップウォッチの計測は、メモリの中だけにあるので、再読み込みで失われます。計測の途中(動いている・一時停止中で未保存・ポモドーロが動いている)に、再読み込み・タブやウィンドウを閉じる・別のページへ移るをしようとすると、
ブラウザの「このサイトを離れますか? 行った変更が保存されない可能性があります」の確認が出ます(`ui/js/components/leaveGuard.js`)。

- 確認の文面は、ブラウザが決めます(アプリからは変えられません)。
- iPad / iPhone の Safari など、この確認を出さないブラウザもあります(その場合は、止められません)。また、ブラウザやOSが強制的に終了させたときは、防げません。
- アプリ自身が再読み込みする場面(更新のお知らせの「更新」、バックアップの復元、全データ削除)でも、同じ確認が出ます。
